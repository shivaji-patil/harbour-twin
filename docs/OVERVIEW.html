Harbour Twin

A 3D computer copy of a harbour, built only from free public data, that tracks ships, finds the ones that are not announcing themselves, plans for floods, and checks its own accuracy.

01In one minute

A digital twin is a working computer copy of a real place. Harbour Twin is a 3D copy of Vancouver Harbour (and St. John's Harbour) made only from free public data: laser scans of the ground, satellite photos and radar, building outlines, tide gauges and the radio messages ships broadcast about where they are (AIS).

It answers three practical questions, and shows its working for each:

  • Which ships are out there, and are any of them silent? It compares ships seen by satellite radar with ships announcing themselves over AIS. A ship the radar sees but that is not announcing itself is worth a closer look.
  • Where would the sea reach in a flood? It works out, building by building, the water level at which the sea actually reaches it, not just "everything below a line".
  • Can the data be trusted? Every dataset is scored against the most accurate one available (laser scans) and must pass published accuracy specifications before it is used.

05Finding ships that do not announce themselves

Large ships must broadcast AIS: who they are and where they are, every few seconds. Some don't: their equipment is off, broken, or deliberately switched off. Satellite radar sees ships whether or not they broadcast, day or night, through cloud. Comparing the two is a core task in maritime domain awareness.

The comparison needs ship positions recorded at the moment the satellite passes overhead (about 02:02 and 14:21 UTC over Vancouver, each repeating every 12 days). The software predicts the next pass.

Honest status. The ship finding works on real radar images. The matching step is tested with made-up data so far, because the bundled ship recording does not overlap a satellite pass. Recording ships during the next pass (path D below) produces the first real comparison.

06How we know the results are right

Every elevation dataset goes through this before it is used. The results are in code/data/vancouver/QC_REPORT.md.

What the checks caught

  • A standard tool was wrong by up to a metre. The common mapping library (PROJ) converts Canadian heights to the global reference with an error of 0.30 m in Vancouver and 1.05 m in St. John's. The pipeline does the conversion explicitly, and a test makes sure it stays right.
  • Published building heights are often wrong. A 190.8 m tower was listed as 10 m tall in OpenStreetMap. 717 such disagreements are flagged for a person to review rather than silently "fixed".
  • A bridge looked like a ship to the radar detector, found by looking at the results on the radar image.
  • A second city broke two assumptions: a missing software dependency, and a tide gauge in St. John's that does not publish the usual height reference. Its level is now converted another way, and cross-checked.

08Reproduce it yourself

Pick the path that matches what you want. Each one builds on the ones before it.

Before you start: download the whole harbour-twin folder (Google Drive gives you a .zip; unzip it). Open a terminal in the unzipped folder. Linux and macOS work directly; on Windows, use WSL (Windows Subsystem for Linux).

A. Just look at it

Needs: Python 3 (any recent version) and an internet connection for the 3D library and base map.

cd code
python3 -m http.server 8765 --directory web

Open http://127.0.0.1:8765 in Chrome, Edge or Firefox. For St. John's open http://127.0.0.1:8765/?aoi=stjohns. Stop it with Ctrl+C.

Expect: downtown Vancouver in 3D, ships moving in the harbour, a panel on the left with layers, flood planner and data-quality numbers. Tick "SAR ship detections" to see the radar layer.

Opening web/index.html by double-clicking does not work: browsers block a page from reading its own data files unless it is served, which is what the first command does.

B. Run the checks

Needs: Python 3.11 or newer, Node.js 18 or newer, and make.

cd code
make setup        # installs Python packages and the 3D-model validator (about 30 s)
make test         # the automated checks
make validate     # checks every 3D building tile against the official standard

Expect: 67 passed, 3 skipped, then {"files":69,"errors":0,"warnings":0}. The 3 skipped checks need the large files. To include them, copy them in and run the checks again:

cp -r ../products/data/* data/
make test         # now 70 passed
make serve        # same viewer as path A, using the installed Python

C. Rebuild everything from the original sources

Needs: path B done, and a normal internet connection. It reads only the parts of each dataset it needs, not whole files.

make data                 # Vancouver: every step, about 4 minutes
make test validate        # the same checks, now on what you just built
make data AOI=stjohns     # St. John's, same pipeline, different settings file
make test AOI=stjohns

Expect: progress messages for each step ("step lidar done in 13 s" and so on), then the same checks passing. Numbers can move slightly if a source publishes newer data.

D. Record your own ships, and compare them with radar

Needs: path B done and a free key from aisstream.io (sign in, copy the API key).

echo "AISSTREAM_API_KEY=paste-your-key-here" > .env
make passes               # when the radar satellite next passes over
make record MIN=120       # start about an hour before that pass; records 2 hours
make ais                  # cleans the tracks, finds radar ships, matches them

Expect: after the satellite image appears in the public catalogue (usually 1 to 3 days after the pass), make ais reports how many radar ships were matched, how many are dark-vessel candidates, and how many AIS ships the radar did not see. The viewer's SAR panel shows the same.

Recording adds to any earlier recording. To keep them apart, move the old one first: mv data/cache/vancouver/ais_raw.jsonl data/cache/vancouver/ais_raw_old.jsonl.

E. Serve it like a product (Docker)

Needs: the large files in data/ (path B or C) and Docker with the Compose plugin.

docker compose up --build        # first run downloads the images (a few minutes)

Expect, once the publish step has exited: the viewer at http://localhost:8333/harbour-twin/web/index.html, served from object storage; the data as a web service and map tiles (OGC API) at http://localhost:5000; and the catalogue at http://localhost:8080. Stop with Ctrl+C, then docker compose down.

09Limits worth knowing

  • The flood planner is a planning screen: it uses still water and the shape of the ground, not waves, wind or drainage.
  • The radar matching has not yet been run on a real ship recording made during a satellite pass (see section 5).
  • How bright a spot must be to count as a ship was set by inspecting real images, not from a labelled training set.
  • AIS comes from volunteer receivers, so coverage is uneven and many vessels never report their type.
  • Buildings newer than the laser scan fall back to published heights, and are labelled as such.

10Words used here

AIS
Automatic Identification System: radio messages in which ships report their identity, position, speed and course.
SAR (radar)
Synthetic Aperture Radar: a satellite sends microwaves and records the echo. Works at night and through cloud; metal ships echo brightly against a dark sea.
Sentinel-1 / -2
European Space Agency satellites: Sentinel-1 carries radar, Sentinel-2 takes colour images. Their data is free.
Lidar
Laser scanning from aircraft. Measures the ground and rooftops to within centimetres; the most accurate height data used here.
Dark vessel
A ship seen by sensors such as radar but not reporting over AIS. Here always a candidate, for a person to review.
CFAR
Constant False Alarm Rate: a standard radar method that calls a spot a target only if it is much brighter than its own surroundings.
Vertical datum
The "zero" that heights are measured from. Different datasets use different zeros, metres apart; mixing them is a common, silent error.
Digital twin
A working computer copy of a real place, built from measurements and kept checkable.
STAC
SpatioTemporal Asset Catalog: a standard way to describe and find map and satellite data; used here both to find inputs and describe outputs.
DTED, GeoPackage
Standard map-file formats used on devices that work without internet, such as ships and drones.
CityJSON
An open format for 3D city models (the JSON form of CityGML), read by city-planning tools. The buildings are exported to it as simple closed blocks.
OGC API - Features
A standard web interface for map data: any GIS can ask it for "buildings in this box" or "flagged buildings" and get them back.
Object storage
Cloud file storage such as Amazon S3. Publishing the products there lets anyone read them over the web without a special server.
I3S
The 3D format ArcGIS uses for scene layers. The buildings are also delivered as an I3S package, checked down to individual roof heights.
3D Tiles
An open standard for streaming 3D city models to a web browser.
